# Simpsons 当日集金サイト改善設計

## 目的

`simpsons-team-os` の `codex/fee-collector` ブランチにある Google Apps Script 製の当日集金サイトを、実際の台帳 `Simpsons_集金台帳_試作版` と整合する運用状態へ整理する。既存の小さな構成は維持し、集金当日に必要な操作の安全性と履歴の見やすさを高める。

対象スプレッドシート ID:

`1yVT9_c1RVdnosvZlN3r2bse6B3NtJo9JvKDggqDI61E`

## 現状確認

実装済みの構成は次の通り。

- `fee-collector/Code.gs`: Apps Script のデータ取得、受領、取消、試合完了処理
- `fee-collector/Index.html`: 画面構造
- `fee-collector/App.html`: ブラウザ側の操作と描画
- `fee-collector/Styles.html`: スマホ向けUI
- `fee-collector/appsscript.json`: Apps Script設定

台帳には `試合`、`参加者`、`受領履歴`、`当日集金` の4タブがあり、実装が参照する3タブの列定義は既存コードと一致している。

## 採用方針

現在の Apps Script + Google Sheets 構成を継続する。外部バックエンドや認証、PayPay API、スタメン画像読み取りは今回の範囲に追加しない。

理由:

1. 既存の実装と台帳を最小変更で運用テストへ進められる。
2. 受領の正式記録を台帳に残すという現在の設計を維持できる。
3. ユーザーが明示していない外部サービスや自動化を増やさない。

## 振る舞い

### 試合選択

- 初期表示は、シート上の順序で `完了` / `中止` ではない最初の試合を選ぶ。
- 手動選択中は過去・未来を含む全試合を表示する。
- 試合完了時は、完了した試合より後にある最初の未完了試合へ移動する。後続がなければ、先頭の未完了試合へ移動する。
- 深夜0時など時刻だけを理由に自動切替しない。

### 受領

- 現金300円とPayPay確認を同じ `受領履歴` に記録する。
- サーバー時刻、受領ID、試合ID、選手ID、金額、支払方法、状態、有効なメモを1行へ追加する。
- Apps Script のロックと有効受領の再確認により、連打・同時操作時も同じ試合・選手の二重受領を防ぐ。
- 受領成功後は未収一覧から受領済み一覧へ移し、受領票を表示できる。

### 取消

- 取消は `受領履歴` の行削除ではなく、状態を `取消` に変更する。
- 取消後は対象選手を未収へ戻す。
- 画面上は有効な受領一覧と分けて、取消履歴を確認できるようにする。
- 取消済み記録を再度取消しても、追加変更なしで安全に終了する。

## データフロー

1. `getBootstrap(preferredGameId)` が試合一覧、選択試合、参加者、有効受領、取消履歴を取得する。
2. `recordPayment(payload)` がロックを取得し、対象参加者と有効受領額を再確認してから追記する。
3. `cancelReceipt(receiptId)` がロックを取得し、対象行の状態とメモだけを更新する。
4. `completeGame(gameId)` がロック下で状態を `完了` にし、次の選択試合を含む新しい状態を返す。
5. ブラウザは返却された状態だけを描画し、一覧の順序と集計をサーバー側の値に合わせる。

## エラー処理

- 試合、選手、支払方法、受領IDがない場合は日本語のエラーを返す。
- 既に有効受領がある場合は成功扱いにせず、最新状態を返して画面を同期する。
- 台帳の必須タブがない場合は、どのタブが必要かをエラーに含める。
- UIの通信失敗はトーストで通知し、ローディング状態を解除する。
