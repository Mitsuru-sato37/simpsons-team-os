# Instagram 制作モジュール設計

## 目的

`Mitsuru-sato37/simpsons-team-os` にInstagram向け試合画像制作の運用モジュールを追加する。試合前の STARTING LINEUP と試合後の GAME RESULT / GAME STATS / FEATURE PLAYER を独立して呼び出せるようにし、既存の当日集金アプリとは独立起動させる。同じ試合の共通情報は `MatchContext` として共有する。

## 確認済みの基準

Google Drive の `Simpsons_試合後SNS標準運用ガイド_v2.1`（文書ID `1wx-wUouhFd2-HZxAFxuAy9S-atoBn0A9oEzODPv3V3c`）を試合後制作の正本とする。DriveではGAME RESULTの `空MASTER` と `SAMPLE`、GAME STATSの `SAMPLE`、FEATURE PLAYERの `基準デザイン` と `完成例` を確認した。GAME STATSの `空MASTER` とSTARTING LINEUPの関連Driveフォルダはいまは空である。

- GAME RESULT: Canva Design ID `DAHWk9bIJ3U`（A案・レイヤー分け済）を複製し、チーム名、先攻／後攻による左右配置、スコア、日付、会場、曜日だけを更新する。二桁スコアのレイアウトを確認する。
- GAME STATS: Canva Design ID `DAHWxMb6kxg` を複製し、得点、安打、四死球、盗塁、長打、打点の数字と対戦相手、日付、会場を更新する。6項目名、枠、ロゴ、背景、装飾、配色は保持する。相手の個別スタッツ、追加ロゴ、マイナス系指標は入れない。
- FEATURE PLAYER: Driveの基準デザインと完成例を参照する。写真主体、少要素のスポーツグラフィックを基本に、名前、成績、短い英語コピーと日本語の一言、写真配置を試合ごとに調整する。ユーザー指定のゴースト入りSimpsonsロゴだけを使用する。
- STARTING LINEUP: 現行制作方法を維持し、新規MASTER化や構成変更をしない。
- 不明な事実は推測しない。MASTER取得・複製が確認できない場合も停止し、確認を求める。新規AI画像生成へのフォールバックは禁止する。

## リポジトリ現状

対象リポジトリはGoogle Apps Script製の `fee-collector/` とNode標準テストから成る。Codex環境ではCanvaとGoogle Driveの接続ツールが利用でき、指定された2つのCanva MASTERを読み取りで確認済みである。これらの接続ツールはCodexの会話から操作するもので、Apps Script実行環境内から呼び出せるものではない。そのため制作モジュールは、Codexがサービスツールを使う順序・条件・検証方法を定める制作ルール／スキルと、外部サービスに依存しない検証可能なデータ定義で構成する。Apps Scriptの `doGet` 等既存入口や共有ランタイム名前空間へInstagram機能を混在させない。依存追加、Canva API資格情報、独自認証・バックエンドを導入しない。

## アーキテクチャ

`MatchContext` は `matchId`, `date`, `opponent`, `venue` を共有し、試合前後で必要な値（会場、先攻／後攻、スコア、チームスタッツ、選手情報等）を任意項目として持つ。利用するフローで必要な事実が欠落していれば入力検証で停止する。

公開フローは「試合前制作」と「試合後制作」の2つに分け、片方だけを呼び出せるCodexスキル／ルールとして定義する。各フローは共有スキーマの `MatchContext` を受け取り、制作で使う事実と不足情報を検証する。試合前はSTARTING LINEUPの現行制作手順を使い、試合後はGAME RESULT、GAME STATS、FEATURE PLAYERを個別に制作できる。入口間は互いを呼び出さず、いずれも集金アプリを参照しない。

Canvaツールで指定MASTERを読み、複製を作成してから複製デザインの編集トランザクションを開始する。編集可能なテキスト／画像要素を読み、ガイドで許可された要素だけを書き換える。編集後プレビューを確認し、Canvaへの確定保存前にユーザーへプレビューを提示して明示承認を得る。元MASTERへの編集は禁止する。複製作成失敗、MASTER ID不一致、固定要素への変更、必須情報不明、またはレイアウト崩れがあれば停止する。Canva接続にはデザイン画像の書き出し操作がないため、承認後のPNGはCanva画面から取得し、Google Driveの確認済み保存先へアップロードする。ブラウザーでの書き出し、ファイル取得、Driveアップロードのいずれかを確認できない場合は未保存として報告する。保存先が特定できない場合は確認し、参照用SAMPLE／空MASTERを出力先にしない。STARTING LINEUPでは既存の制作方法を維持する。画像生成処理は持たない。

## データと運用フロー

1. ユーザーは対象試合と、必要なスコアブック／選手写真などの参照を提示する。
2. Codexは対象フローに必要な事実を抽出し、`MatchContext` 形式で整合性を確認する。不明情報だけユーザーへ確認する。
3. 試合前／試合後のどちらか一方を独立して開始できる。試合後の3成果物も個別に作成できる。
4. CodexはCanva MASTERを複製し、指定された可変項目だけを更新してプレビューする。FEATURE PLAYERはDriveの基準デザイン／完成例も参照する。
5. ユーザーがプレビューを承認した後にCanvaへ保存し、完成画像をGoogle Driveの所定フォルダへ保存する。投稿は手動のままとし、自動投稿、スケジュール、Instagram認証は追加しない。

## エラー処理

- 日付、対戦相手、会場、match_id等、実行対象に必要な共通項目が欠けていれば制作要求を作らない。
- 試合後数値、先攻／後攻、対象選手の事実が未確定なら対象出力を保留し、不明点を列挙する。
- 指定MASTERを取得・複製できないとき、Drive参照元が見つからないとき、複製元と出力先を区別できないときは停止する。
- MASTER固定要素を変更しようとする要求は検証エラーとする。
- AI画像生成、別MASTER、新規テンプレートを代替として使用しない。

## 検証

Nodeの標準テストランナーで、共通情報の検証、入口の独立性、3種類の試合後制作ルール、Canva IDと許可フィールド、固定6スタッツ、必須情報不足時の停止、AI生成フォールバックなしを確認する。既存の `node --test tests/fee-collector-logic.test.mjs` も実行し、集金機能が保たれることを確認する。Canva／Driveの操作そのものはCodex接続ツールを使った実作業で確認する。Canva確定保存は毎回プレビュー提示後にユーザーの明示承認を得て実行する。

## 範囲外

- Instagramへの自動投稿、投稿スケジュール、認証・API資格情報
- 新規AI画像生成、AI生成画像を使う代替フロー
- 集金機能とのデータ連携、画面統合、単一起動依存
- スタメン画像の選手認識や参加者台帳への登録
- Canva / Driveの認証基盤を新設すること
