# ローカル動画解析 MVP

試合MP4からイニング切り替わり**候補**を探し、画面で確認・訂正する独立モジュールです。動画本体はPC内で読み取り専用として扱い、クラウドには送信しません。`fee-collector/` やInstagram制作とは接続していません。リポジトリには現時点で共通のTeam OSチャット画面がないため、MVPの入口はローカルのデスクトップ画面です。

## 起動

WindowsでPython（Tkinter、OpenCV、NumPy）とFFmpeg/FFprobeを使用できる状態にしてください。`Simpsons イニングチェッカー.vbs` または `start-video-analysis.cmd` をダブルクリックすると、コンソールを表示せずアプリを起動します。アプリのウィンドウ名は「Simpsons イニングチェッカー」です。Pythonの `pythonw.exe` は `%LOCALAPPDATA%\Python\pythoncore-*` から探します。FFmpegはPATHとWinGetのGyan.FFmpeg配置先から自動で探すので、コマンド入力や環境変数の設定は不要です。起動中にエラーが起きた場合はダイアログが表示され、詳細を `.local/video-analysis/startup-error.log` に保存します。

1. 「動画を選択」からローカルMP4を選び、「解析する」を押します。
2. 粗解析は全体を10秒間隔・幅640pxで読み、従来の画面全体の色比率に加え、画面を4×4に分けた色の配置変化を調べます。
3. 色配置の検出では、前後の安定状態の差、80〜240秒にわたる変化の経路、変化中の動き、変化した領域数を組み合わせ、急な単発変化を除外します。現在の固定広角カメラでのFBでは、画面右端（ホームベース側）の変化割合も条件にしています。
4. 従来の画面全体の色変化候補は前後45秒を1秒間隔で再解析し、開始・終了を推定します。色配置で見つけた候補は粗解析で推定した開始・終了を保持します。
5. 候補一覧に推定開始・終了が表示されます。候補を選ぶと推定値が入力欄に入り、必要なら手修正して正解／不正解と一緒に保存できます。保存済みの修正区間は「確認」と表示します。
6. 候補に出なかった切り替わりは「見逃した切り替わりを追加」から開始・終了時刻と理由を保存できます。後日「保存済み結果を開く」から再確認できます。

表示スコアと開始・終了は**正解確率やプレー状態の認識結果ではありません**。色比率と4×4の色配置から、持続的な画面状態の変化を推定します。フィードバック済みの試合映像7区間では、正解区間の配置差が8.3〜20.2、誤検出として確認した区間が21.0以上の例が多く、配置差の範囲・変化の経路・変化中の動き・右端領域の寄与を組み合わせました。右端条件は現在の固定広角カメラに依存する暫定条件です。人物検出やプレー状態認識はまだなく、カメラ移動・背景色・ベンチ映像による誤検出、または見逃しがありえます。候補と区間は必ず映像で確認してください。

解析結果はリポジトリ内の無視対象 `.local/video-analysis/` にJSONとして保存します。元動画の絶対パス、容量、解析日時、設定、ロジックバージョン、候補時刻・スコア、正誤、切り替わり区間の開始・終了、見逃し区間、理由を記録します。解析ごとに新しいJSONを作り、以前の結果と元動画は上書きしません。別PCへの自動同期はありません。FBは自動学習されません。今回のロジック1.2では、保存済みFBを人が比較して調整材料にしました。今後もFBを追加しただけではロジックは変わらず、検証とコード更新が必要です。実動画や解析結果をGitへ追加しないでください。

## 今回の検証と次の課題

2026-10-08、`GX010430.mp4`（3395.4秒）をローカルで通し解析しました。候補は **11:10 (49), 25:02 (93), 35:12 (52), 39:30 (61), 43:24 (89)** です。数値は100点満点のヒューリスティックスコアで、確率ではありません。詳細解析は候補周辺を1秒間隔で処理し、フィードバック可能なJSONを `.local/video-analysis/` に保存しました。

候補前後の映像サンプルを見ると、複数候補が打者・捕手周辺の動きを拾っているように見えます。11.7GBのMP4を最後まで処理できることは確認できましたが、5件すべてがイニング切り替わりかは未確定です。UI部品の初期化と4秒のサンプル抽出は確認済みです。次は保存済み結果を画面で開き、映像を見て正解・不正解・正しい時刻を記録し、そのラベルを使ってしきい値を調整します。分割、打席検出、チャット操作は次フェーズです。
